7:3

VibeCoding : BlackBox, 속도 ↑

구현/초안은 AI 가 검토는 사람이

Explore -> Plan -> Action -> Commit
        검토    검토      검토
사람이 AI가 낸 산출물을 검토해야 함.

Explore : 진행해야 하는 내용을 이해, 구조이해
SPEC.md
PRD.md
CLAUDE.md

Plan : 설계 
PLAN.md
DESIGN.md
Phase{#}.md

Action : 점진적으로 구현하도록 Phase별로
Phase{#}.md 를 점진적으로 개발

문서와 코드는 동기화(Sync)가 되어야 함

산출물들이 리뷰할 수 있어야 함.

병목 지점에 대해서 비용을 낮추기 위해서
 1) 가독성(클린코드)
 2) 개발자 역량
 3) 리뷰 단위

Agentic Engineering에서의 ROI는 결국 리뷰 비용을 얼마나 줄이느냐에 달려 있다.
이를위해서는가독성과분해능력을중심으로설계해야한다.

1) 가독성 확보 (클린코드)이 좋을수록리뷰비용은줄어든다.
• 가독성이 좋을수록 코드 이해 시간이 줄어들고, 
• 리뷰 속도가 빨라지며, 전체 개발 시간이 단축된다. 
• 클린코드는 곧 비용 절감이다

2) 리뷰 가능한 단위로 분해 (Phase 설계)
• 코드를 한번에 크게 생성하는 것이 아니라, 사람이 충분히 검토할 수 있는 단위로 나누어 개발해야 한다. 
• “리뷰 가능한크기”로 나누는 것이 핵심이다.

3) 개발 역량 강화
• 개발자의 역량은 Agentic Engineering의 효율을 크게 좌우한다.
• 클린코드에 대한 고민과 리팩토링에 대한 경험이 많을수록, 일관된 가독성을 가진 코드를 설계할 수 있다.
• 개발 경험이 풍부할수록, AI가 생성할 코드의 형태를 예측할 수 있고, 리뷰 가능한 수준으로 Phase를 나누어 계획할 수 있다.
• 자료구조/ 알고리즘 이해도가 높을수록, 문제 분해 능력이 향상되며 AI가 사용할 구현 방식까지 예측할 수 있다.


Phase별 개발에서 작성한Plan 문서를 바탕으로 (Pang KATA), 사람이 리뷰 가능한 수준으로 Phase를 다시 설계해보자.
단순히작업단계를나누는것이아니라, 각Phase가 명확한 의도와검증기준을갖고, 사람이이해하고판단할수있도록구조화하는 것이 목표다.

수행방법
1. 기존 Plan 문서를 분석한다.
2. 작업을의미있는단위(Phase)로 다시분리한다. (리뷰 가능한단위로나눌것)
3. 각 Phase에 아래 내용을 포함한다
• 목적(Why)
• 수행작업(What)
• 검증방법(Verify)
• 리뷰포인트(Review)

Regression / Safety 테스트 작성
Safety(안정성) 테스트 예 참고
• 이상한값을마구넣어보기
• 예외일으켜보기, 잘못된입력넣어보기
• 극단적인, 못된사용자가있다고가정하고테스트를해보기

다음 역할을 해주는 SubAgent를 생성
• SubAgent1 : 문서 정합성 검증 (문서간 충돌, 중복, 모순 등)
• SubAgent2 : AI Action (Plan을 코드로 생성)
• SubAgent3 : Test Verify (Unit Test/E2E Test)
• SubAgent4 : Compliance Verify (Plan에 맞는 코드 생성 확인)

SubAgent3과 4는 병렬로 실행 가능

하고, 동작 테스트를 진행해보자.
